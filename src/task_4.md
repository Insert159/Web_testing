# Задание 4. Протоколы HTTP и HTTPS

##  Схему работы HTTPS-протокола

### Шаг 1: ClientHello 
- Цель этапа: Инициировать соединение и предложить серверу параметры шифрования.
- Какой риск устраняет: Без этого этапа браузер и сервер будут «говорить на разных языках» шифрования, что сделает защищенное соединение невозможным.
- Детали: Браузер отправляет на сервер версию TLS, случайный набор байтов (Client Random) и список поддерживаемых алгоритмов шифрования (Cipher Suites).

### Шаг 2: ServerHello + Certificate
- Цель этапа: Предоставить браузеру цифровое удостоверение сервера.
- Какой риск устраняет: Защита от атаки «человек посередине» (MITM). Пользователь должен быть уверен, что общается именно с нужным сайтом, а не с мошенником.
- Детали: Сервер выбирает алгоритм шифрования из списка браузера, присылает свой Server Random и отправляет SSL-сертификат (содержит публичный ключ, доменное имя и подпись удостоверяющего центра).

### Шаг 3: Certificate Verify & Key Exchange 
- Цель этапа: Проверить подлинность сертификата и безопасно согласовать секретный ключ для шифрования.
- Какой риск устраняет: Перехват данных. Даже если злоумышленник слушает сеть, он не сможет расшифровать трафик, так как ключ передается скрыто.
- Детали: Браузер проверяет сертификат (срок, подпись CA, совпадение домена). Браузер шифрует Pre-Master Secret публичным ключом сервера и отправляет его. Сервер расшифровывает его своим приватным ключом. Обе стороны выводят одинаковый Master Secret.

### Шаг 4: Change Cipher Spec & Finished 
- Цель этапа: Переключиться на безопасный, зашифрованный канал.
- Какой риск устрашает: Защита дальнейшего трафика (содержимого страницы, паролей, cookies) от прослушивания.
- Детали: Браузер отправляет команду «Change Cipher Spec» и зашифрованное проверочное сообщение «Finished». Сервер делает то же самое. Рукопожатие завершено, начинается зашифрованный обмен данными HTTPS.

## Шпаргалка тестировщика по HTTP-кодам

### Группа 1xx (Informational) — «Все в порядке, продолжай»

| Код | Что видит пользователь | Что происходит на самом деле | Как тестировать | Куда эскалировать |
| :--- | :--- | :--- | :--- | :--- |
| 100 Continue | Ничего. Процесс загрузки файла идет. | Клиент спрашивает разрешение отправить большой файл, сервер дает добро. | Отправить `POST` запрос с заголовком `Expect: 100-continue`. | Бэкенд |

### Группа 2xx (Success) — «Запрос выполнен успешно»

| Код | Что видит пользователь | Что происходит на самом деле | Как тестировать | Куда эскалировать |
| :--- | :--- | :--- | :--- | :--- |
| 200 OK | Страница загрузилась, API вернул данные. | Сервер обработал запрос и вернул ожидаемый результат. | Открыть любую страницу сайта. | Фронтенд / Бэкенд |
| 201 Created | В админ-панели: «Новый пользователь добавлен». | Сервер успешно создал новый ресурс (например, запись в БД). | Отправить валидный `POST` запрос на создание объекта. | Бэкенд |

### Группа 3xx (Redirection) — «Ресурс перемещен»

| Код | Что видит пользователь | Что происходит на самом деле | Как тестировать | Куда эскалировать |
| :--- | :--- | :--- | :--- | :--- |
| 301 Moved Permanently | В адресной строке `http://` автоматически сменился на `https://`. | Сайт навсегда переехал на новый адрес. | Открыть сайт по HTTP (без `s`) и проверить Network вкладку. | DevOps |
| 304 Not Modified | Страница открылась мгновенно. | Браузер использовал свою локальную копию, так как контент не изменился. | Обновить страницу (F5) и посмотреть размер ответа. | Бэкенд |

### Группа 4xx (Client Error) — «Ошибка на стороне клиента»

| Код | Что видит пользователь | Что происходит на самом деле | Как тестировать | Куда эскалировать |
| :--- | :--- | :--- | :--- | :--- |
| 400 Bad Request | «Неверный запрос». | Сервер не понял запрос из-за синтаксической ошибки (например, кривой JSON). | В `POST` запросе сломать структуру JSON. | Фронтенд |
| 401 Unauthorized | Страница логина. «Требуется авторизация». | Пользователь не предоставил данные для входа (отсутствует токен). | Отправить запрос к приватному API без заголовка `Authorization`. | Фронтенд / Бэкенд |
| 403 Forbidden | «У вас нет прав для просмотра этой страницы». | Пользователь авторизован, но у него недостаточно прав для этого действия. | Попробовать зайти в `/admin` под обычным пользователем. | Бэкенд |
| 404 Not Found | Страница не найдена («Знаменитый 404»). | Ресурс с таким URL не существует на сервере. | Открыть `21-school.ru/ne_sushestvuyushaya_stranica`. | DevOps |

### Группа 5xx (Server Error) — «Ошибка на стороне сервера»

| Код | Что видит пользователь | Что происходит на самом деле | Как тестировать | Куда эскалировать |
| :--- | :--- | :--- | :--- | :--- |
| 500 Internal Server Error | «Сайт упал с ошибкой». | На сервере произошло необработанное исключение (ошибка в коде, проблема с БД). | Отправить запрос, который гарантированно вызывает баг. | Бэкенд |
| 502 Bad Gateway | «Ошибка 502. Плохой шлюз». | Прокси-сервер (например, Nginx) не дождался ответа от приложения. | Отключить backend-сервис на пару секунд. | DevOps |
| 503 Service Unavailable | «Сайт на техническом обслуживании». | Сервер перегружен или его специально отключили на обновление. | Нагрузить сервер или попросить администратора включить режим обслуживания. | DevOps |
