## 2. Анализ флагов для критичных данных

### Критичные cookie

- `__Secure-access-token`
- `__Secure-refresh-token`
- `__Secure-user-id`
- `__Secure-ETC`
- `__Secure-ext_xcid`
- `abt_data` (тоже содержит токеноподобное значение)

### Анализ флагов на примере `__Secure-access-token` и `__Secure-refresh-token`

> У остальных Secure-токенов ситуация аналогична.

| Флаг | Значение | Что означает |
|------|----------|---------------|
| Secure | (есть) | Cookie передаётся только по HTTPS. Это обязательно для access/refresh токенов. |
| HttpOnly | (есть) | Cookie недоступен для чтения через JavaScript (`document.cookie`). Защита от XSS-атак. |
| SameSite | `Lax` | Cookie не отправляется при межсайтовых GET-запросах (например, переходе с email или внешней ссылки), но отправляется при переходе по ссылке с того же сайта. Это защита от CSRF, но менее строгая, чем `Strict`. |

### Важно

> Префикс `__Secure-` гарантирует, что браузер примет такой cookie, только если он установлен с флагом `Secure` и через HTTPS.

---

### Хорошо

- Использован префикс `__Secure-` для всех критичных cookie
- Флаг `Secure` везде присутствует
- Флаг `HttpOnly` везде присутствует — токены нельзя украсть через XSS
- `SameSite=Lax` для access/refresh токенов — хорошая защита от CSRF
- Долгий срок жизни (1 год) допустим для refresh token, но при условии, что на сервере есть механизм отзыва

### Риски

| Риск | Описание | Рекомендация |
|------|----------|--------------|
| `SameSite=None` у `__Secure-ETC` и `__Secure-ext_xcid` | Разрешает отправку cookie на сторонние сайты. Если эти cookie содержат идентификатор сессии — это опасно. | Выставить `SameSite=Lax` или `Strict`, если они не нужны для кросс-доменных запросов. |
| Долгий срок жизни `__Secure-access-token` (1 год) | Обычно access token живёт 15–60 минут. Долгоживущий access token увеличивает риск угона (даже с HttpOnly). | Уменьшить TTL access token до часов/минут, использовать refresh token для продления. |
| `abt_data` имеет `SameSite=None` | Если внутри есть данные сессии или личная информация, это риск утечки на сторонние сайты. | Аудит содержимого и ограничение SameSite. |

### Описание cookie `guest` (Добавдение в корзину)

| Параметр | Значение |
|----------|----------|
| Имя | `guest` |
| Значение | `true` |
| Тип | Сессионный (Session) — удаляется при закрытии браузера |
| Domain | `.ozon.ru` |
| Path | `/` |
| Secure | нет (пустая ячейка) |
| HttpOnly | нет |
| SameSite | не указан (по умолчанию `Lax`) |
| Priority | `Medium` |

### Почему именно `guest` отвечает за корзину?

1. Появился только после добавления товара — прямая корреляция

2. Сессионный тип — логично: корзина гостя не должна сохраняться после закрытия браузера

3. Значение `true` — флаг, указывающий, что текущий пользователь — гость с активной корзиной

4. Отсутствие флагов Secure/HttpOnly — значение не критичное, можно читать через JS (например, для отображения количества товаров)
